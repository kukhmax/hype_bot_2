# Trading Bot (Hyperliquid) — Realtime ADX/ATR, свечи из тиков, Redis, авто-ордеры (DRY_RUN)

Этот бот подключается к WebSocket Hyperliquid, собирает свечи из mid-тиков, вычисляет сигналы ADX/ATR в реальном времени, рассылает уведомления в Telegram и позволяет открыть позицию кнопкой (по умолчанию в режиме DRY_RUN).

## Возможности
- Реальное построение OHLC свечей из тиков по заданным таймфреймам.
- Хранение последних 200 свечей в Redis (на каждый `pair`+`TF` отдельный ключ).
- Сигналы на основе ADX/ATR (пороговые значения из подписки пользователя).
- Dedup-замок сигналов (Redis NX+EX), чтобы не спамить до следующей свечи.
- Менеджер позиций в Redis и заготовка авто-исполнения ордеров.
- Настраиваемое логирование (консоль + файл `bot.log`).

## Быстрый старт
1. Подготовьте `.env` в папке `app` (минимум):

   ```env
   BOT_TOKEN=ваш_telegram_token
   REDIS_HOST=redis
   REDIS_PORT=6379
   # Для реальных ордеров (опционально)
   HL_API_KEY=...
   HL_API_SECRET=...
   # По умолчанию DRY_RUN включён; чтобы отправлять реальные ордера:
   DRY_RUN=false
   ```

2. Запустите docker-compose:

   ```bash
   cd app
   docker compose up -d --build
   ```

3. Проверьте логи:

   ```bash
   docker compose logs -f bot
   # или по имени контейнера
   docker logs -f app-bot-1
   ```

4. Напишите боту `/start` и оформите подписку через меню.

## Архитектура
- WebSocket: `services/market_ws.py` — подключается к Hyperliquid WS, принимает тики, передаёт в пайплайн.
- Свечи: `services/candles.py` — собирает OHLC из тиков, хранит 200 последних свечей в Redis.
- Сигналы: `services/signal_engine.py` — считает ADX/ATR, принимает решение LONG/SHORT/None.
- Дедуп: `services/signal_lock.py` — Redis-замок `siglock:{user}:{pair}:{tf}m` c TTL = размер TF.
- Позиции: `services/position_manager.py` — хранит открытую позицию пользователя.
- Ордеры: `services/order_executor.py` — заготовка REST-вызова (по умолчанию DRY_RUN).
- Уведомления: `services/notifier.py` — отправляет сообщение с кнопкой «Открыть».
- Бот/роутеры: `bot.py`, `handlers/*` — FSM подписок, просмотр подписок, обработка нажатия кнопки.
- Логи: `core/logger.py` — формат и вывод (консоль + `bot.log`).

## Ключи Redis
- Свечи: `ohlcv:{PAIR}:{TF}m` — список JSON-объектов `{"t","o","h","l","c"}` (t — ms).
- Подписки: `user:{user_id}:subscriptions` — `HSET sub_id -> json`.
- Dedup-замок: `siglock:{user_id}:{PAIR}:{TF}m` — ключ с TTL.
- Позиция: `position:{user_id}:{PAIR}` — состояние открытой позиции.

## Подписки пользователя
Через меню:
- «📡 Получать сигналы» — запускается диалог FSM: пара → таймфрейм → ADX → ATR → риск %.
- «📋 Активные подписки» — список действующих подписок.

По каждой подписке бот будет:
1) Собирать свечи по указанному TF.
2) Считать ADX/ATR и принимать решение.
3) Ставить dedup-замок на период TF, чтобы не было повторов.
4) Отправлять сообщение с кнопкой открытия позиции.

## Кнопка «Открыть» и ордера
- Нажатие вызывает callback вида `trade:{pair}:{signal}:{risk}`.
- `handlers/trade.py` вызывает `OrderExecutor` и фиксирует позицию через `PositionManager`.
- По умолчанию `OrderExecutor` работает в `DRY_RUN`. Для реального исполнения:
  - задайте `HL_API_KEY`, `HL_API_SECRET` и `DRY_RUN=false` в `.env`,
  - доработайте подпись/аутентификацию под актуальные требования Hyperliquid.

## Тонкости и рекомендации
- Формат WS: используем поле `mid` (или из `data.mid`) и `coin` — проверьте актуальный формат Hyperliquid и при необходимости поправьте парсинг в `market_ws.py`.
- Таймфреймы: берутся из подписок пользователей, указываются в минутах (например, `5m`).
- Количество свечей: хранится 200 последних; можно изменить в `RedisCandleStore.append()`.
- Numpy/Pandas: используются для расчёта индикаторов. Убедитесь, что ресурсы контейнера позволяют.
- Безопасность: не храните ключи в репозитории; используйте `.env`/секреты окружения.

Что такое ADX (сила тренда)

- ADX (Average Directional Index) измеряет, насколько тренд «сильный», но не важна его сторона (вверх или вниз).
- Значения обычно:
  - 0–20 — тренда почти нет, рынок «болтается» в боковике.
  - 20–25 — тренд только начинается, ещё слабый.
  - 25–40 — нормальный, уверенный тренд.
  - 40+ — очень сильный тренд, часто уже перегретый.
Минимальный ADX в боте

- Это фильтр: «Не присылай сигнал, если тренд слишком слабый».
- Логика в движке такая:
  - Мы считаем ADX по последним свечам.
  - Берём последнюю свечу и смотрим её ADX.
  - Если последний_adx <= твой_порог_ADX → бот просто не даёт сигнал, даже если направление +DI / -DI вроде бы говорит LONG/SHORT.
- Примеры:
  - Поставил ADX = 20 → будешь получать больше сигналов, включая слабые/грязные тренды.
  - Поставил ADX = 30 → будут приходить только те, где тренд уже окреп.
  - Поставил ADX = 40 → очень жёсткий фильтр, сигналов мало, только на мощных движениях.
Что такое ATR (волатильность)

- ATR (Average True Range) показывает, насколько сильно цена обычно гуляет за одну свечу:
  - Чем выше ATR, тем больше средний диапазон движения (в пунктах/долларах).
  - Чем ниже ATR, тем рынок более «тихий», цена почти стоит.
- ATR измеряется в тех же единицах, что цена:
  - Если BTC стоит 50 000, ATR=50 → свече нормально сходить ±50.
  - ATR=500 → сейчас свечи ходят ±500, рынок «разгоняется».
Минимальный ATR в боте

- Это второй фильтр: «Не присылай сигнал, если движения слишком мелкие».
- Логика:
  - После расчёта ATR по свечам, движок берёт последнюю свечу и смотрит её ATR.
  - Если последний_atr <= твой_порог_ATR → сигнал не отправляется.
- Примеры:
  - На спокойном рынке ATR маленький → твой порог не выполняется, бот молчит.
  - Когда рынок оживает, ATR растёт → начинают проходить фильтр и появляются сигналы.
- Смысл:
  - Ты отсекаешь ситуации, где формально есть тренд, но движения крошечные, и в реальных деньгах это «ни о чём».
Как это работает вместе в твоём движке При проверке сигнала бот делает по сути:

1. Считает ADX/ATR по последним свечам.
2. Берёт последнюю свечу и проверяет:
   - last_adx > твой_порог_ADX ?
   - last_atr > твой_порог_ATR ?
3. Только если оба условия выполнены, смотрит направление (+DI / -DI) и выдаёт:
   - LONG , если +DI > -DI
   - SHORT , если наоборот
   - иначе — ничего.
Как выбирать значения на практике

- Если хочешь много сигналов , но более шумных:
  - ADX порог 15–20
  - ATR — маленький (зависит от инструмента; для начала можно взять значение, которое часто встречается по истории).
- Если хочешь реже, но более «качественные» тренды :
  - ADX 25–30
  - ATR — такой, чтобы отсечь тихие периоды (посмотри по свечам, какие уровни ATR считаешь «мелочью»).
