# Trading Bot (Hyperliquid) — ML Adaptive Supertrend, свечи из тиков, Redis, авто-ордеры (DRY_RUN)

Этот бот подключается к WebSocket Hyperliquid, собирает свечи из mid-тиков, вычисляет сигналы по индикатору **ML Adaptive Supertrend с подтверждением ADX ≥ 20** в реальном времени, рассылает уведомления в Telegram и позволяет открыть позицию кнопкой (по умолчанию в режиме DRY_RUN).

## Возможности
- Реальное построение OHLC-свечей из тиков по заданным таймфреймам.
- Хранение последних 200 свечей в Redis (на каждый `pair`+`TF` отдельный ключ).
- Сигналы по алгоритму **ML Adaptive Supertrend + ADX ≥ 20** без ручного подбора порогов.
- Dedup-замок сигналов (Redis NX+EX), чтобы не спамить до следующей свечи.
- Менеджер позиций в Redis и заготовка авто-исполнения ордеров.
- Настраиваемое логирование (консоль + файл `bot.log`).

## Архитектура
- WebSocket: `services/market_ws.py` — подключается к Hyperliquid WS, принимает тики, передаёт в пайплайн.
- Свечи: `services/candles.py` — собирает OHLC из тиков, хранит 200 последних свечей в Redis.
- Индикатор: `services/ml_supertrend.py` — ML Adaptive Supertrend + расчёт ATR/ADX и сигнала LONG/SHORT/None.
- Кэш индикаторов: `services/indicator_cache.py` — хранит последний снимок (centroids, cluster, ST, dir, ADX) по каждой паре/TF.
- Дедуп: `services/signal_lock.py` — Redis-замок `siglock:{user}:{pair}:{tf}m` c TTL = размер TF.
- Позиции: `services/position_manager.py` — хранит открытую позицию пользователя.
- Ордеры: `services/order_executor.py` — заготовка REST-вызова (по умолчанию DRY_RUN).
- Уведомления: `services/notifier.py` — отправляет сообщение с кнопкой «Открыть».
- Подписки: `services/subscription_service.py`, `handlers/subscriptions.py` — FSM подписок, CRUD, первичный расчёт.
- Бот/роутеры: `bot.py`, `handlers/*` — старт, меню, подписки, торговые действия.
- Логи: `core/logger.py` — формат и вывод (консоль + `bot.log`).

## Ключи Redis
- Свечи: `ohlcv:{PAIR}:{TF}m` — список JSON-объектов `{"t","o","h","l","c"}` (t — ms).
- Подписки: `user:{user_id}:subscriptions` — `HSET sub_id -> json`.
- Dedup-замок: `siglock:{user_id}:{PAIR}:{TF}m` — ключ с TTL.
- Позиция: `position:{user_id}:{PAIR}` — состояние открытой позиции.

## Подписки пользователя
Через меню:
- «📡 Получать сигналы» — запускается диалог FSM: **пара → таймфрейм → риск %**.
- «📋 Активные подписки» — список действующих подписок с возможностью отмены.

По каждой подписке бот будет:
1) Собирать свечи по указанному TF (из тиков Hyperliquid).
2) На закрытии свечи считать ML Adaptive Supertrend + ADX и принимать решение.
3) Ставить dedup-замок на период TF, чтобы не было повторов сигналов по этой паре/TF/пользователю.
4) Отправлять сообщение с кнопкой открытия позиции.

## Кнопка «Открыть» и ордера
- Нажатие вызывает callback вида `trade:{pair}:{signal}:{risk}`.
- `handlers/trade.py` вызывает `OrderExecutor` и фиксирует позицию через `PositionManager`.
- По умолчанию `OrderExecutor` работает в `DRY_RUN`. Для реального исполнения:
  - задайте `HL_API_KEY`, `HL_API_SECRET` и `DRY_RUN=false` в `.env`,
  - доработайте подпись/аутентификацию под актуальные требования Hyperliquid.

## Алгоритм и логика работы

### Общий поток данных

1. Пользователь в Telegram нажимает `/start` и через меню создаёт подписку:
   - выбирает **пару** (например, `HYPE`, `SOL`, `ETH`),
   - выбирает **таймфрейм** (в минутах: `1`, `5`, `15` и т.п.),
   - задаёт **Risk %** — долю депозита, которой готов рискнуть.
2. `SubscriptionService.create_subscription`:
   - сохраняет подписку в Redis (`user:{user_id}:subscriptions`);
   - обновляет кэш отслеживаемых пар;
   - запускает фоновую задачу:
     - загрузить историю свечей через REST (`HistoryLoader.preload_for_pair_tf`);
     - выполнить **первичный расчёт ML Adaptive Supertrend** и при необходимости отправить сигнал.
3. В фоне работает `MarketWS`:
   - подключается к Hyperliquid WS (`allMids`);
   - фильтрует поток только по тем парам, которые есть в подписках;
   - передаёт тики в `CandlePipeline` → `CandleBuilder` строит OHLC-свечи;
   - готовые свечи сохраняются в Redis (`RedisCandleStore.append`).
4. Когда по паре/TF закрывается свеча:
   - `MarketWS` берёт последние свечи из Redis (`to_df`);
   - передаёт их в `MLAdaptiveSupertrendEngine.evaluate`;
   - при наличии нового сигнала LONG/SHORT:
     - ставит dedup-замок (`SignalLock`);
     - отправляет уведомление в Telegram (`Notifier.send_signal`) с кнопкой «Открыть».
5. При нажатии на кнопку:
   - хэндлер `handlers/trade.py` разбирает callback,
   - через `OrderExecutor` рассчитывает объём позиции по Risk % (в DRY_RUN просто логирует),
   - через `PositionManager` фиксирует состояние позиции пользователя.

### ML Adaptive Supertrend (services/ml_supertrend.py)

Алгоритм построен на идеях Pine-скрипта **ML Adaptive Supertrend**:

1. **Подготовка данных**
   - Берутся последние N свечей (по умолчанию 200, для расчёта ~120+ баров).
   - Формируется `DataFrame` с колонками: `open`, `high`, `low`, `close`, `timestamp`.
   - Считается ATR с заданной длиной (например, `atr_len = 10`).
2. **Кластеризация волатильности (k-means)**
   - Берётся серия ATR за последние `training_len` баров (например, 100).
   - Инициализируются 3 центроида:
     - High volatility,
     - Medium,
     - Low — как 75/50/25% диапазона ATR.
   - Выполняется несколько итераций k-means:
     - каждый ATR относится к ближайшему центроиду;
     - центроиды пересчитываются как среднее своих кластеров.
   - Текущий ATR (последний бар) относится к одному из кластеров, и берётся его `assigned_centroid` — адаптивный «средний ATR» для текущего режима волатильности.
3. **Построение Supertrend**
   - Рассчитывается средняя цена `hl2 = (high + low) / 2`.
   - Для последнего бара считаются:
     - верхняя граница: `upper = hl2 + factor * assigned_centroid`,
     - нижняя граница: `lower = hl2 - factor * assigned_centroid`.
   - Из Redis поднимается предыдущий Supertrend (линии и направление):
     - если цена не пробивает границы, линии «протягиваются» (как в классическом Supertrend);
     - при пробое происходит смена направления (`dir`).
   - Сама линия Supertrend — либо верхняя, либо нижняя граница (в зависимости от направления).
4. **ADX и подтверждение сигнала**
   - По этой же серии свечей считается ADX.
   - Используется жёсткий порог `ADX ≥ 20`:
     - если ADX < 20 → сигнал не генерируется, даже при смене направления тренда.
5. **Генерация сигнала**
   - Сигнал появляется только когда:
     - изменилось направление Supertrend (бычий ↔ медвежий),
     - и при этом `ADX ≥ 20`.
   - Возвращаемые сигналы:
     - `"LONG"` — смена в бычий тренд,
     - `"SHORT"` — смена в медвежий тренд,
     - `None` — нет нового сигнала.
6. **Кэширование состояния индикатора**
   - Через `IndicatorCache` сохраняется снимок:
     - centroids кластеров ATR,
     - текущий cluster и assigned,
     - линия Supertrend и направление,
     - ADX последнего бара.
   - Это удобно для диагностики и визуализации (например, можно потом нарисовать график).

### Поведение без REST-истории

Если REST Hyperliquid по какой-то причине не отдаёт историю (код 422 или пустой ответ):
- `HistoryLoader` логирует предупреждение и просто возвращает `0` свечей;
- первичный сигнал не рассчитывается, но дальше WS начинает собирать свечи с нуля;
- как только накопится достаточно баров (минимум ~120), ML-движок начнёт работать целиком по данным из WS.

## Тонкости и рекомендации
- Формат WS: используем поле `mids` в канале `allMids` и `coin` — при изменении формата Hyperliquid можно поправить парсинг в `market_ws.py`.
- Таймфреймы: берутся из подписок пользователей, указываются в минутах (`1`, `5`, `15` и т.п.); внутри ключей Redis используются как `{TF}m`.
- Количество свечей: хранится 200 последних; можно изменить в `RedisCandleStore.append()`.
- Numpy/Pandas: используются для расчёта индикаторов. Убедитесь, что ресурсы контейнера позволяют.
- Безопасность: не храните ключи в репозитории; используйте `.env`/секреты окружения.

Что такое ADX (сила тренда)

- ADX (Average Directional Index) измеряет, насколько тренд «сильный», но не важна его сторона (вверх или вниз).
- Значения обычно:
  - 0–20 — тренда почти нет, рынок «болтается» в боковике.
  - 20–25 — тренд только начинается, ещё слабый.
  - 25–40 — нормальный, уверенный тренд.
  - 40+ — очень сильный тренд, часто уже перегретый.
Минимальный ADX в боте

- Это фильтр: «Не присылай сигнал, если тренд слишком слабый».
- Логика в движке такая:
  - Мы считаем ADX по последним свечам.
  - Берём последнюю свечу и смотрим её ADX.
  - Если последний_adx <= твой_порог_ADX → бот просто не даёт сигнал, даже если направление +DI / -DI вроде бы говорит LONG/SHORT.
- Примеры:
  - Поставил ADX = 20 → будешь получать больше сигналов, включая слабые/грязные тренды.
  - Поставил ADX = 30 → будут приходить только те, где тренд уже окреп.
  - Поставил ADX = 40 → очень жёсткий фильтр, сигналов мало, только на мощных движениях.
Что такое ATR (волатильность)

- ATR (Average True Range) показывает, насколько сильно цена обычно гуляет за одну свечу:
  - Чем выше ATR, тем больше средний диапазон движения (в пунктах/долларах).
  - Чем ниже ATR, тем рынок более «тихий», цена почти стоит.
- ATR измеряется в тех же единицах, что цена:
  - Если BTC стоит 50 000, ATR=50 → свече нормально сходить ±50.
  - ATR=500 → сейчас свечи ходят ±500, рынок «разгоняется».
Минимальный ATR в боте

- Это второй фильтр: «Не присылай сигнал, если движения слишком мелкие».
- Логика:
  - После расчёта ATR по свечам, движок берёт последнюю свечу и смотрит её ATR.
  - Если последний_atr <= твой_порог_ATR → сигнал не отправляется.
- Примеры:
  - На спокойном рынке ATR маленький → твой порог не выполняется, бот молчит.
  - Когда рынок оживает, ATR растёт → начинают проходить фильтр и появляются сигналы.
- Смысл:
  - Ты отсекаешь ситуации, где формально есть тренд, но движения крошечные, и в реальных деньгах это «ни о чём».
Как это работает вместе в твоём движке При проверке сигнала бот делает по сути:

1. Считает ADX/ATR по последним свечам.
2. Берёт последнюю свечу и проверяет:
   - last_adx > твой_порог_ADX ?
   - last_atr > твой_порог_ATR ?
3. Только если оба условия выполнены, смотрит направление (+DI / -DI) и выдаёт:
   - LONG , если +DI > -DI
   - SHORT , если наоборот
   - иначе — ничего.
Как выбирать значения на практике

- Если хочешь много сигналов , но более шумных:
  - ADX порог 15–20
  - ATR — маленький (зависит от инструмента; для начала можно взять значение, которое часто встречается по истории).
- Если хочешь реже, но более «качественные» тренды :
  - ADX 25–30
  - ATR — такой, чтобы отсечь тихие периоды (посмотри по свечам, какие уровни ATR считаешь «мелочью»).
