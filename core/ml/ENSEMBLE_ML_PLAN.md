# 🧠 Ensemble ML для Intraday + Scalping — Технический План

## Концепция

Внедрение ансамблевого ML-фильтра (Ensemble Signal Filter) в существующий торговый бот. Ансамбль из 3 легковесных моделей анализирует рынок с разных углов и выдаёт единый взвешенный скор уверенности. Если скор превышает **динамический порог** — сигнал от стратегии пропускается дальше. Если нет — фильтруется.

**Ключевой принцип:** ML-модели НЕ генерируют сигналы самостоятельно. Они работают как **второй фильтр** (после стратегии, перед Gemini AI), повышая качество существующих сигналов.

---

## 📐 Архитектура Ансамбля (3 модели)

### Модель 1: Momentum Scorer
**Задача:** Оценить силу и направление текущего импульса.

| Фича               | Описание                                    |
|---------------------|---------------------------------------------|
| `rsi`               | RSI(14) — перекупленность/перепроданность    |
| `rsi_delta`         | Изменение RSI за последние 3 свечи          |
| `ema_21_slope`      | Наклон EMA(21) за 5 свечей (%)              |
| `ema_50_slope`      | Наклон EMA(50) за 5 свечей (%)              |
| `close_vs_ema_21`   | (Close - EMA21) / ATR — отклонение от EMA   |
| `close_vs_ema_200`  | (Close - EMA200) / ATR — позиция в тренде   |
| `di_diff`           | DI+ - DI- (направленность тренда)           |

**Выход:** `momentum_score` ∈ [0, 1] — вероятность, что импульс подтверждает сигнал.

---

### Модель 2: Volatility Scorer
**Задача:** Оценить, благоприятна ли текущая волатильность для входа.

| Фича                | Описание                                      |
|----------------------|-----------------------------------------------|
| `atr_normalized`     | ATR / Close — нормализованная волатильность    |
| `atr_ratio`          | ATR(current) / ATR(SMA 20) — волат. vs среднее|
| `bb_width`           | Ширина Bollinger Bands (уже в DF)             |
| `bb_width_change`    | Изменение BB Width за 3 свечи                 |
| `bb_position`        | (Close - BB_Lower) / (BB_Upper - BB_Lower)    |
| `high_low_range`     | (High - Low) / ATR текущей свечи              |
| `volume_ratio`       | Volume / SMA_Volume(20) (если доступен)       |

**Выход:** `volatility_score` ∈ [0, 1] — вероятность, что волатильность подходит для входа.

---

### Модель 3: Structure Scorer
**Задача:** Оценить рыночную структуру (тренд, диапазон, переход).

| Фича                 | Описание                                   |
|-----------------------|--------------------------------------------|
| `adx`                 | Сила тренда (ADX 14)                      |
| `adx_slope`           | Изменение ADX за 5 свечей                  |
| `ema_alignment`       | 1 если EMA21>EMA50>EMA200, -1 обратное, 0 |
| `bb_squeeze`          | bool: BB_Width < 20-period min BB_Width    |
| `higher_highs`        | Кол-во последовательных растущих High (5)  |
| `lower_lows`          | Кол-во последовательных падающих Low (5)   |
| `close_vs_local_mid`  | Close vs середина диапазона (20 candles)   |

**Выход:** `structure_score` ∈ [0, 1] — вероятность, что структура поддерживает сигнал.

---

## 🔀 Механизм Ансамблирования

### Формула финального скора:

```
ensemble_score = w1 * momentum_score + w2 * volatility_score + w3 * structure_score

где по умолчанию w1 = 0.35, w2 = 0.30, w3 = 0.35
```

### Динамический Threshold (Адаптивный Порог)

Порог принятия сигнала **не фиксирован**, а рассчитывается по истории последних 100 сделок:

```python
class DynamicThreshold:
    """Адаптирует threshold на основе последних N сделок."""
    
    def __init__(self, window: int = 100, base_threshold: float = 0.55):
        self.window = window
        self.base_threshold = base_threshold
        self.trade_history = []  # список (score, pnl)
    
    def get_threshold(self) -> float:
        if len(self.trade_history) < 20:
            return self.base_threshold  # Мало данных — базовый порог
        
        recent = self.trade_history[-self.window:]
        wins = [t for t in recent if t['pnl'] > 0]
        winrate = len(wins) / len(recent)
        
        # Если WinRate высокий (>60%) → снижаем порог (больше сделок)
        # Если WinRate низкий (<40%) → повышаем порог (строже фильтруем)
        adjustment = (winrate - 0.5) * 0.2  # ∈ [-0.1, +0.1]
        
        threshold = self.base_threshold - adjustment
        return max(0.3, min(0.8, threshold))  # Ограничиваем диапазон
    
    def report_trade(self, score: float, pnl: float):
        self.trade_history.append({'score': score, 'pnl': pnl})
        if len(self.trade_history) > self.window * 2:
            self.trade_history = self.trade_history[-self.window:]
```

### Решение:
```
IF ensemble_score >= dynamic_threshold → PASS (сигнал идёт на Gemini AI)
IF ensemble_score <  dynamic_threshold → BLOCK (сигнал отклонён ML)
```

## 🧪 Тип ML моделей

### Рекомендация: **Logistic Regression** (scikit-learn)

| Критерий          | Оценка                                            |
|-------------------|----------------------------------------------------|
| **Скорость**      | ⚡ ~0.001 сек на предсказание                      |
| **Память**        | ⚡ ~1-5 KB на модель                                |
| **Обучение**      | ⚡ ~0.1 сек на 1000 строк                           |
| **Интерпретация** | ✅ Полностью прозрачные коэффициенты                |
| **Зависимости**   | ⚠️ scikit-learn (~50 MB в Docker)                   |

### Альтернатива: **Gradient Boosting (LightGBM)**

| Критерий          | Оценка                                            |
|-------------------|----------------------------------------------------|
| **Скорость**      | ⚡ ~0.005 сек на предсказание                      |
| **Память**        | ~5-20 KB на модель                                  |
| **Обучение**      | ~1 сек на 5000 строк                               |
| **Точность**      | ✅ Обычно лучше ловит нелинейные паттерны           |
| **Зависимости**   | ⚠️ lightgbm (~30 MB в Docker)                      |

**Рекомендую начать с LogisticRegression** — это проще, прозрачнее и достаточно для фильтра. Если не хватит точности — переключиться на LightGBM, заменив 1 строку кода.

## 🔄 Процесс Обучения Моделей

### Вопрос: На чём обучать?

Модели обучаются на **результатах бэктеста**. Алгоритм:

1. Прогоняем бэктест стратегии на исторических данных (3000+ свечей)
2. Для каждой сделки записываем:
   - ML-фичи на момент входа
   - Результат сделки (profit/loss → label: 1/0)
3. Обучаем 3 модели на этом датасете
4. Сохраняем в `core/ml/data/*.pkl`

### Периодическое переобучение:
- **Через Telegram:** Кнопка «🧪 Тест Стратегий» может сразу переобучать ML
- **Автоматически:** Раз в N часов (опционально, через asyncio task)
- **При старте бота:** Если моделей нет — тренируем на лету при инициализации

---

## 🔒 Режим работы без обученных моделей (Fallback)

Если модели не обучены (первый запуск, ошибка файлов):
- `EnsembleFilter.evaluate()` возвращает `score = 1.0` (пропускает все сигналы)
- Бот работает как раньше — без ML фильтрации
- В логах: `⚠️ ML модели не загружены. Фильтрация отключена.`
