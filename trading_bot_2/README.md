## 🚀 Как начать пользоваться (Инструкция)

### 1. Подготовка сервера (или локального ПК)
Убедитесь, что у вас установлен `docker` и `docker-compose`. Проект написан на Python 3.13 и запускается внутри изолированного контейнера.

Клонируйте этот репозиторий и перейдите в папку проекта:
```bash
git clone <ваш-репозиторий> ./trading_bot_2
cd trading_bot_2
```

### 2. Настройка переменных окружения
Вам необходимо настроить ключи доступа к Telegram и Google Gemini.
Создайте файл конфигурации:
```bash
cp .env.example .env
nano .env
```

Отредактируйте `.env` файл, указав ваши данные:
```env
# Токен вашего бота, полученный в @BotFather
TELEGRAM_BOT_TOKEN=789123456:AAH...

# API ключ от Google AI Studio для нейросетевого анализа (Gemini 1.5)
GEMINI_API_KEY=AIzaSy...

# Торговая пара по умолчанию (строго формат биржи MEXC Futures)
DEFAULT_SYMBOL=BTC_USDT
```

### 3. Сборка и Запуск (через Docker Compose)
Чтобы запустить бота на фоне, выполните:
```bash
docker-compose up -d --build
```
Бот соберет образ (это займет 1-2 минуты) и запустится. Вы можете перейти в Telegram и отправить команду `/start` вашему боту.

## ⚙️ Подробная логика работы и архитектура

Весь процесс работы бота четко структурирован и проходит через несколько слоев валидации, чтобы минимизировать ложные сигналы.

### Хронология обработки одного события:

1. **Telegram Menu (`bot/telegram_bot.py`)**  
   Пользователь вводит команду `/start` и нажимает на кнопку запуска мониторинга в интерфейсе бота. Бот создает экземпляр оркестратора `MultiTFEngine` и передает ему выбранную торговую пару (например, `SOL_USDT`).

2. **Оркестратор таймфреймов (`core/multi_tf_engine.py`)**  
   Класс `MultiTFEngine` запускает **два параллельных WebSocket потока** исторических и живых данных:
   - **DataFeed 1h (Часовой)**: Отвечает исключительно за определение глобального тренда.
   - **DataFeed 15m (Пятнадцатиминутный)**: Отвечает за поиск точек входа и микроструктуру свечей.

3. **Сбор данных (`core/data_feed.py` -> `core/candle_buffer.py`)**  
   Каждый поток подключается к MEXC Futures через WebSocket. Как только закрывается новая 15-минутная свеча, DataFeed передает управление обратно в `MultiTFEngine`.

4. **Глобальный фильтр тренда (`indicators/calculator.py`)**  
   Оркестратор сразу смотрит в буфер 1h (часовой). С помощью `calculate_indicators` вычисляются часовые EMA (10, 20, 50). Если EMA выстроены строго вверх (10 > 20 > 50), тренд считается **LONG**. Если вниз — **SHORT**.

5. **Поиск паттернов (`core/signal_engine.py` -> `patterns/*.py`)**  
   Далее запускается `SignalEngine.analyze()`, который работает с 15-минутным графиком. Он прогоняет буфер через все 12 зарегистрированных паттернов из папки `patterns` (возврат к уровню, пинг-понг, поглощения, сужение волатильности и др.). Если набирается достаточное количество паттернов (по умолчанию `MIN_PATTERNS_TO_SIGNAL=3`) в одном направлении — движемся дальше.

6. **Фильтрация по индикаторам (`core/signal_engine.py`)**  
   Функция `_indicator_confirms` проверяет внутренние 15m индикаторы: ADX (сила тренда > 25), RSI (зоны перепроданности/перекупленности) и CCI. Если индикаторы подтверждают направление паттернов — формируется сырой сигнал.

7. **Кросс-проверка таймфреймов (`core/multi_tf_engine.py`)**  
   Сырой 15-минутный сигнал сравнивается с глобальным часовым трендом. Если они не совпадают (например, на 15m медвежий паттерн, а 1h тренд бычий) — сделка игнорируется (контртрендовый фильтр).

8. **AI Анализ Gemini (`ai/gemini_client.py`)**  
   Если все математические фильтры пройдены, `SignalEngine` отправляет "фотографию" рынка (цены, индикаторы, найденные паттерны) в текстовом виде нейросети Google Gemini. 
   Нейросеть выступает в роли независимого эксперта, оценивая структуру пробоя, качество паттернов и выставляет оценку уверенности в сделке (Confidence, от 0 до 100%).

9. **Вычисление Confluence Score (`core/multi_tf_engine.py`)**  
   В методе `_calc_confluence` собирается итоговая оценка надежности сделки. Весовые коэффициенты: Оценка AI (40%), Сила и кол-во паттернов (25%), Сила тренда 1h (20%), Согласование таймфреймов (15%). Если итоговый балл >= `MIN_CONFIDENCE`, сигнал идет в продакшн.

10. **Доставка сигнала Пользователю (`bot/telegram_bot.py` -> `bot/signal_formatter.py`)**  
    Бот присылает пользователю красиво оформленное сообщение с рассчитанными динамическими Stop-Loss и Take-Profit (на базе индикатора ATR). К сообщению крепятся инлайн-кнопки "✅ ВОЙТИ В СДЕЛКУ" и "⏭ ПРОПУСТИТЬ". Включается таймер на 5 минут: если пользователь не реагирует, сигнал помечается как просроченный (Устарел).

## 🐳 Команды Docker и Логирование

Бот работает изолированно с помощью `docker-compose`. Это самый надежный способ его запуска и мониторинга.

### Управление состоянием (Запуск и Остановка)
- **Сборка и запуск в фоне:** `docker-compose up -d --build` (Используйте всегда, когда вносите изменения в код)
- **Обычный запуск (без сборки):** `docker-compose up -d`
- **Остановка бота:** `docker-compose stop`
- **Полное удаление контейнера:** `docker-compose down`
- **Перезагрузка:** `docker-compose restart`

### Логирование
Все текстовые логи бота (все найденные паттерны, подключения к WS, ошибки сети) автоматически пишутся как в консоль Docker, так и сохраняются в файл на сервере (благодаря монтированию Docker Volumes).

- **Смотреть логи онлайн:** `docker-compose logs -f` (или с ограничением по длине: `docker-compose logs --tail 100 -f`)
- **Смотреть файл физически:** `tail -f logs/bot.log`

> Файл логов `logs/bot.log` ротируется внутри (ограничение до 10 МБ с хранением последних 3 бекапов), поэтому он не забьет место на сервере.

## 🤖 Команды Telegram Бота

Интерфейс бота полностью кнопочный, но вы можете использовать следующие прямые команды прямо в чате:

| Команда | Действие |
|---------|----------|
| `/start` | Вызывает главное меню настроек, позволяет запустить мониторинг на выбранной монете. |
| `/pair BTC_USDT` | Моментально переключает рабочую торговую пару (обязательно использовать MEXC Futures формат с `_USDT`). |
| `/status` | Выводит актуальный статус оркестратора, показывая, сколько свечей 15m и 1h успешно загружено, и идет ли мониторинг. |
| `/stop` | Принудительно отключает механизмы мониторинга и отписывается от WebSocket биржи. |

## 🗂 Структура проекта

Дерево каталогов бота и назначение ключевых модулей:

```text
trading_bot_2/
├── .env                  # Ваш файл с секретными API-ключами
├── docker-compose.yml    # Конфигурация контейнера и проброса volumes
├── Dockerfile            # Скрипт сборки изолированной Python 3.13 среды
├── main.py               # Главный файл (создает папки и вызывает Telegram-бота)
├── config.py             # Центральный файл настроек (таймфреймы, кулдауны, ATR)
├── ai/
│   └── gemini_client.py  # Промпты и запросы к нейросети Google Gemini
├── bot/
│   ├── telegram_bot.py     # Обработчик кнопок и команд Telegram, запуск MultiTFEngine
│   ├── signal_formatter.py # Класс для красивого форматирования текста сигнала (Markdown)
│   └── keyboards.py        # Inline-клавиатуры для меню бота
├── core/
│   ├── multi_tf_engine.py  # Оркестратор. Связывает воедино 15m и 1h DataFeed
│   ├── signal_engine.py    # Математический движок. Прогоняет паттерны и индикаторы
│   ├── data_feed.py        # Асинхронное получение OHLCV через MEXC WebSocket/REST
│   └── candle_buffer.py    # Кольцевой буфер `deque` для хранения последних 300 свечей
├── indicators/
│   └── calculator.py       # Вычисление EMA, ATR, RSI, ADX с помощью numpy/pandas_ta
├── patterns/
│   ├── base.py             # Базовый абстрактный класс для всех свечных паттернов
│   ├── level_patterns.py   # Логика паттернов уровней ("Возврат за уровень")
│   ├── ema_patterns.py     # Логика паттернов скользящих ("Подхват скользящей")
│   └── registry.py         # Список регистрации всех паттернов
└── utils/
    └── logger.py           # Настройка системы логгирования (библиотека loguru)
```
